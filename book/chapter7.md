# 第 7 章 读懂几个主流榜单

前六章按机制讲，这一章倒过来，从读者最常看到的榜单出发，看每个头条数字背后走了哪几步。每个榜单一张卡片，统一回答五个问题：

- **头条数字**是什么；
- **怎么判**：每道题谁来判、对照什么；
- **怎么合**：题内、多次运行、整套题各怎么合；
- **会不会随别的模型变**：加一个新模型，老分动不动；
- **读的时候注意**：最容易引用错的地方。

涉及的机制都在前面讲过，卡片里只指回去。

<a id="7-1"></a>

## 7.1 Artificial Analysis

### 智能指数

- **头条数字**：十个组件的加权和乘以 100，AA-Omniscience 拆成两项，实际是 11 项加权（[5.1 节](chapter5.md#5-1)）。Agents 类占 30%，编程占 20%，通用占 30%，科学推理占 20%。
- **怎么判**：各组件自己出分。
  - Terminal-Bench 4.0：66 道题各跑 3 次，用 mini-swe-agent 框架，全部测试通过才算对；
  - SciCode：288 个子问题各跑 3 次；
  - HLE 和 AA-LCR：GPT-5.6 Luna (medium) 做等价判定；
  - AA-Omniscience：6000 道私有题，准确率和"1 − 幻觉率"拆成两个组件；
  - GDP.pdf：100 道题各跑 5 次，GPT-5.6 Luna 逐条判细则，全部通过才算；
  - CritPt：交给官方评分服务器；
  - AutomationBench-AA：657 道题，碰了护栏整题记 0。
- **怎么合**：两个 Elo 类组件先用 clamp((Elo − 500)/2000) 压到 0 到 1，再按权重相加。温度方面，非推理模型用 0，推理模型用 0.6，API 失败最多重试 30 次。
- **会不会随别的模型变**：两个 Elo 类组件在模型进入指数时冻结，之后不再变（[3.8 节](chapter3.md#3-8)）。
- **读的时候注意**：指数的小版本之间不可比，厂商发布页引用的常常是更早的版本（[AA 方法页](https://artificialanalysis.ai/methodology/intelligence-benchmarking)）。

### GDPval-AA

- **头条数字**：Elo，锚定 DeepSeek V4.1 Flash (max) = 1600，95% 区间用 sandwich 估计。
- **怎么判**：用 GDPval 的 220 道题，模型在 Stirrup 框架里最多跑 250 轮，交出文件。两个模型的交付物配成一场，每场从三个判官（Claude Opus 5、GPT-5.6 Sol、Gemini 3.8 Flash）里抽一个盲评。
- **怎么合**：平局各算半胜，用 Crowd-BT 拟合（[3.4 节](chapter3.md#3-4)）。配对先均衡抽样，再让分数相近的模型多比。
- **会不会随别的模型变**：会，但进入指数的那个分是冻结的。
- **读的时候注意**：
  - 这里的判官和 GDP.pdf 的单一判官 GPT-5.6 Luna 不是一回事，两者容易混。
  - 第二版锚的是人类专家 = 1000，所以 DeepSeek-V4 报告里的 1554 只能和第二版的数比（[3.8 节](chapter3.md#3-8)）。

### AA-Briefcase

- **头条数字**：Elo，锚定 GPT-5.5 (medium) = 1000。
- **怎么判**：91 道题、4 个场景，三个分项。
  - 分析质量和呈现：判官两两比较；
  - 细则：由另一组判官判，同一条细则固定由同一个判官判，再把通过率改写成假想的对局。
- **怎么合**：三项分别拟合 Crowd-BT 再汇总。
- **会不会随别的模型变**：会。细则分本来是绝对的，改写成对局以后，也会随对手池变化（[3.7 节](chapter3.md#3-7)）。
- **读的时候注意**："假想对局"怎么造 AA 没写，造法不同能差 100 多分。

### Harvey LAB-AA

- **头条数字**：每题"判了全部细则通过的判官占比"的平均，每题只能取 0、⅓、⅔、1（[2.2 节](chapter2.md#2-2)）。不进指数。
- **怎么判**：120 个私有法律任务，每题有 44 到 90 条细则。三个判官（GPT-6 Sol、Grok 4.7、Claude Opus 5.5）各自逐条判。有实质性幻觉的题直接记 0，幻觉由一个判官列举、另一个判官 GPT-6 Sol (high) 对照材料逐条复核。
- **怎么合**：先在每个判官内部看是否全过，再在判官之间平均。
- **会不会随别的模型变**：不会。
- **读的时候注意**：它是"全过"和"比例"差距最大的例子。同一套评测还报逐条通过率，同一份判定在两个口径下可以差出几倍（[2.1 节](chapter2.md#2-1)）。

## 7.2 LMArena 和 Agent Arena

LMArena 在 2026 年 1 月 28 日改名为 Arena，书里沿用旧名。

### 文本榜

- **头条数字**：Elo 刻度上的分数和区间。
- **怎么判**：用户实时提问，两个匿名模型作答，用户投票。
- **怎么合**：平局拆成两个半场，用 BT 拟合，换到 Elo 刻度（[3.3 节](chapter3.md#3-3)）。默认视图带风格控制，对局按频率重新加权，事实性对局是一个默认关闭的开关（[3.5 节](chapter3.md#3-5)）。区间用 Arena-Rank 的闭式算法。
- **会不会随别的模型变**：会，所有分数一起拟合。
- **读的时候注意**：题目分布随用户群变化，私测变体只公开最好的会抬分（[6.2 节](chapter6.md#6-2)）。

### Agent Arena

- **头条数字**：Net Improvement，相对均匀分配基线的提升，单位是百分点。10 月 8 日的榜上，Claude Fable 5.1 (Max) 是 12.66% ±2.05%，排第 3。
- **怎么判**：在真实编程会话里随机分配编排模型，从会话中挖五个信号（[4.1 节](chapter4.md#4-1)）。
- **怎么合**：每个信号用逆倾向加权算出相对均匀分配的净提升，五个等权平均。
- **会不会随别的模型变**：会。基线是所有模型的均匀混合，换一批模型基线就变。
- **读的时候注意**：Confirmed Success 一栏的 16.19% ±2.96% 也是相对基线的提升，不能当成功率引用（[榜单](https://arena.ai/leaderboard/agent)）。

## 7.3 Vals

Vals 维护约 30 个 bench 和一个按行业 GDP 加权的指数，各 bench 的做法差别很大。

### Finance Agent

- **头条数字**：部分分，全过是副指标，两种口径的排名会翻转。
- **怎么判**：v2 由 GPT-5.4、Gemini-3.1-Pro、Claude Sonnet 4.6 三个判官组成评审团，逐项检查。
- **怎么合**：检查项带权重，一票否决项不过整题记 0。
- **会不会随别的模型变**：不会。
- **读的时候注意**：v1.1 用的是另一套，GPT-5.2 判三次取众数（[2.2 节](chapter2.md#2-2)）。页面还画了成本的帕累托曲线。

### Legal Research Bench

- **头条数字**：全过口径。同一个模型全过是 55.29，加权通过率是 90.58。
- **怎么判**：单个判官逐条判细则。
- **读的时候注意**：两个口径差 35 个点，引用时要说清楚是哪个。

### ProofBench

- **头条数字**：100 道题的通过率，页面另报每任务成本。
- **怎么判**：Lean 4 编译判定证明。模型最多迭代 40 轮，只能用 `submit_proof` 提交一次。
- **读的时候注意**：已经有 4 个模型并列满分，这个 bench 在顶端已经分不开了。

### 扑克

- **头条数字**：TrueSkill 保守分 $\mu-\sigma$，换算到以 1000 为基线的刻度（[3.6 节](chapter3.md#3-6)）。
- **会不会随别的模型变**：会。

### 降级怎么记

Vals 把降级到其他模型的任务分开报，给 Claude Fable 5 报了"含降级"和"降级记失败"两个分（[6.1 节](chapter6.md#6-1)，[vals.ai](https://www.vals.ai/benchmarks)）。

## 7.4 Scale SEAL

SEAL 的每个 bench 自己出分，名次另有规则：名次等于 1 加上"区间下界高于本模型区间上界"的模型数，区间重叠就可以并列（[2.4 节](chapter2.md#2-4)）。

### Humanity's Sixth Sense

- **头条数字**：分数和 95% 区间，人类基线是 93.1%。
- **怎么判**：522 道题，其中 288 道图像、234 道视频，Claude Opus 5 逐条判细则。
- **怎么合**：每题跑 3 次取平均，按题做 bootstrap 得 95% 区间（[论文](https://labs.scale.com/papers/humanitys-sixth-sense)）。

### MCP Atlas

- **怎么判**：判官给每个要点 1、0.5 或 0 分。
- **怎么合**：覆盖率达到 0.75 算通过。

### HiL-Bench

- **头条数字**：ASK-F1，即提问精确率和阻塞召回率的调和平均，另报 Pass@3。

## 7.5 MathArena 和 LiveBench

这两个榜都靠换新题对付污染。

### MathArena

- **头条数字**：各竞赛的平均正确率和区间。
- **怎么判**：新竞赛题公布后尽快测，用程序比对最终答案。
- **怎么合**：每题跑 4 次取平均。没跑到的模型–题目组合用项目反应理论补上再平均，区间也用模拟后重新拟合得到（[matharena.ai](https://matharena.ai/)）。
- **读的时候注意**：补出来的格子是统计模型的预测。AIME、HMMT 每届只有 30 道左右的题，区间很宽（[6.3 节](chapter6.md#6-3)）。

### LiveBench

- **怎么判**：只用有客观答案的题，不用 LLM 判官，定期换题。
- **怎么合**：类别内平均后，再对类别平均。
- **读的时候注意**：跨版本比较时要看版本日期（[livebench.ai](https://livebench.ai/)）。

## 7.6 METR 和 Epoch

### METR 时间跨度

- **头条数字**：成功率 50% 处对应的人类耗时。
- **怎么判**：1.1 版有 228 个任务，每个任务标有人类完成耗时。
- **怎么合**：对成功率和人类耗时的对数拟合逻辑回归，读出 50% 处的耗时。区间来自任务族、任务、运行三层的 bootstrap（[1.6 节](chapter1.md#1-6)）。
- **读的时候注意**：和 1.0 版的数字不能直接比。

### Epoch ECI

- **头条数字**：ECI，线性缩放到 Claude 3.5 Sonnet = 130、GPT-5 = 150。当前最高的是 Claude Opus 5.5 的 167，和 GPT-6 Astra 的 166.5 区间重叠，统计上并列。
- **怎么合**：把每个 bench 当成一道大题，联合拟合所有模型的能力（[5.2 节](chapter5.md#5-2)），至少有 4 个 bench 的成绩才给分。
- **会不会随别的模型变**：会，所有模型一起拟合。
- **读的时候注意**：差 0.5 不代表有先后（[epoch.ai](https://epoch.ai/benchmarks/eci)）。

## 7.7 ARC-AGI-3 和 FrontierSWE

### ARC-AGI-3

- **头条数字**：游戏分的平均，同时画每任务成本。
- **怎么判**：每关分是人类首玩动作数和 AI 动作数之比的平方。
- **怎么合**：按关卡号加权成游戏分，游戏分不超过已通关卡的权重占比，所以分数由通关多少和效率共同决定（[1.6 节](chapter1.md#1-6)，[方法](https://docs.arcprize.org/methodology)）。

### FrontierSWE

- **头条数字**：第二版是 34 个工程任务的平均分，当前头名 GPT-6 Astra 是 65.5% ±8.9。
- **怎么判**：每题归一到 0 到 1，跑 5 次，每次 20 小时预算。
- **怎么合**：柱子画平均，须线从最差画到最好，再画成本和运行时间的帕累托前沿。
- **会不会随别的模型变**：第二版不会；第一版会。
- **读的时候注意**：第一版各题报原生指标，头条是按名次算的支配分，两版不能比（[3.7 节](chapter3.md#3-7)，[frontierswe.com](https://www.frontierswe.com/)）。

<a id="7-8"></a>

## 7.8 HealthBench Professional 和 SWE-bench Pro

### HealthBench Professional

- **头条数字**：长度校正后的细则分，乘 100 报。
- **怎么判**：GPT-5.4 当判官，按医生写的带正负分值的细则逐条判，题分可以是负的。
- **怎么合**：主比较每题采样 8 次取平均。在全集平均之后才裁到 0 到 1（[2.1 节](chapter2.md#2-1)）。
- **读的时候注意**：OpenAI 测别家模型时也用自己的判官重跑（[arXiv 2604.27470](https://arxiv.org/abs/2604.27470)）。

### SWE-bench Pro

- **头条数字**：解决率。
- **怎么判**：模型提交补丁，原本失败的测试要通过、原本通过的测试不能坏，两组都过才算解决（[1.2 节](chapter1.md#1-2)）。
- **读的时候注意**：公开、保留、商业三个子集分开报，用的 agent 框架不同，分数也不同（[arXiv 2509.16941](https://arxiv.org/abs/2509.16941)）。

<a id="7-9"></a>

## 7.9 Kaggle Game Arena

- **头条数字**：统一榜的 BT 分。
- **怎么判**：各游戏自己的榜各有算法（[3.6 节](chapter3.md#3-6)、[1.7 节](chapter1.md#1-7)）。
  - 国际象棋：每对模型下 40 局、最弱者记 0；
  - 扑克：每 100 手赢多少个大盲；
  - 狼人杀：博弈均衡排名。
- **怎么合**：统一榜把国际象棋、四子棋、扑克、狼人杀等游戏的对局都化成两两胜负，放进同一个 BT。每个游戏除以自己的对局总数，让每个游戏的总权重相同（[5.3 节](chapter5.md#5-3)）。
- **会不会随别的模型变**：会。
- **读的时候注意**：扑克只剩"赢没赢"，不再计较赢了多少；狼人杀的阵营结构也被拆掉了（[Kaggle 博客](https://www.kaggle.com/blog/unified-game-arena-leaderboard)）。
